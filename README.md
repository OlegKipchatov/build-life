# BuildLife

Задачи, вехи с последовательностью шагов и RPG-профиль персонажа.

## Разработка

Node.js 22+, npm.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
```

Стек: React, TypeScript, TanStack Router и HeroUI. Vite собирает приложение в `dist`. Собственные стили — CSS Modules; Tailwind используется инфраструктурой стилей HeroUI, без utility-классов в компонентах приложения.

## Архитектура

- `src/model.ts` — расписания, опыт, уровни, вехи, шаги и совместимая миграция данных.
- `src/store.tsx` — React state и сохранение `buildlife-v1` в localStorage.
- `src/pages` — задачи, вехи, профиль и настройки.
- `src/components` — общие компоненты, HeroUI-формы и редакторы.
- `tests` — тесты связей, миграции, прогресса и сохранения.

Задачи остаются в единой коллекции. Веха завершается только явно, при наличии хотя бы одного шага и выполнении всех шагов. Выполнение задачи не завершает шаг автоматически. Удаление шага или вехи отвязывает задачи, но не удаляет их.

Сохранены прежние формулы: 100 XP на уровень; задачи дают 10/20/30 XP, переход навыка на следующий уровень добавляет 100 XP связанным характеристикам. Новых наград за вехи не введено: в прежней модели они отсутствовали.

## Данные

Ключ localStorage — `buildlife-v1`. Существующие записи, выбранные иконки, история выполнения и дополнительные legacy-поля сохраняются. Ошибки чтения блокируют перезапись данных. Между доменами Sites и GitHub Pages localStorage не переносится автоматически.

## Публикация

Маршрутизация использует hash history, ресурсы — относительный base, поэтому приложение поддерживает GitHub Pages в `/build-life/`.

После слияния миграции выберите **Settings → Pages → Source: GitHub Actions**. Workflow `pages.yml` собирает и публикует `dist` при push в main или ручном запуске. До слияния прежний `docs/` остаётся неизменным.

Рабочие изменения миграции: https://github.com/OlegKipchatov/build-life/pull/1
